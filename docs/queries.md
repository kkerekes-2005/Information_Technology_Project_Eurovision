## Q01. Which countries have won the contest most often, and when did each one last win?

Author: Kinga Kerekes. File: `sql/queries/q01_wins_by_country.sql`. Constructs: JOIN of four tables, GROUP BY, COUNT, MAX.

```sql
SELECT country.name AS country,
       COUNT(*) AS wins,
       MAX(song_entry.year) AS last_win
FROM performance
JOIN round ON round.round_id = performance.round_id
JOIN song_entry ON song_entry.entry_id = performance.entry_id
JOIN country ON country.country_code = song_entry.country_code
WHERE round.round_type = 'final'
  AND performance.place = 1
  AND song_entry.year BETWEEN 1957 AND 2023
GROUP BY country.country_code, country.name
ORDER BY wins DESC, last_win DESC;
```

## Q06. Which pairs of countries give each other high points in both directions?

Author: Kinga Kerekes. File: `sql/queries/q06_mutual_voting.sql`. Constructs: CTE joined with itself, GROUP BY with HAVING.

```sql
WITH pair_average AS (
    SELECT vote.from_country,
           vote.to_country,
           COUNT(*) AS contests,
           ROUND(AVG(vote.total_points), 2) AS average_points
    FROM vote
    JOIN round ON round.round_id = vote.round_id
    WHERE round.round_type = 'final'
      AND vote.from_country <> vote.to_country
      AND round.year BETWEEN 1975 AND 2015
    GROUP BY vote.from_country, vote.to_country
    HAVING COUNT(*) >= 10
)
SELECT first_country.name AS country_a,
       second_country.name AS country_b,
       a_to_b.average_points AS a_gives_b,
       b_to_a.average_points AS b_gives_a,
       a_to_b.contests AS contests
FROM pair_average AS a_to_b
JOIN pair_average AS b_to_a
  ON b_to_a.from_country = a_to_b.to_country
 AND b_to_a.to_country = a_to_b.from_country
JOIN country AS first_country ON first_country.country_code = a_to_b.from_country
JOIN country AS second_country ON second_country.country_code = a_to_b.to_country
WHERE a_to_b.from_country < a_to_b.to_country
  AND a_to_b.average_points >= 6
  AND b_to_a.average_points >= 6
ORDER BY a_to_b.average_points + b_to_a.average_points DESC;
```

## Q13. How is a new contest registered so that either all of its rows are saved or none?

Author: Kinga Kerekes. File: `sql/queries/q13_new_contest_transaction.sql`. Constructs: INSERT, UPDATE and DELETE inside BEGIN ... COMMIT, a failed statement followed by ROLLBACK.

```sql
--
-- Run each part separately in the pgAdmin Query Tool: select the part and press F5.
-- The ids 104 and 1720 are the next free ones: the load ends at round 103 and entry 1719.
-- The 2024 winner is used as the example (source: eurovisionworld.com/eurovision/2024,
-- checked on 2026-11-15: 591 points, 226 public, 365 jury, running order 21).
-- Part 3 removes it again, so the database ends exactly as the dataset delivered it.

-- Part 1. Register the 2024 contest, its final, the winning entry and its result.
BEGIN;
INSERT INTO contest (year) VALUES (2024);
INSERT INTO round (round_id, year, round_type) VALUES (104, 2024, 'final');
INSERT INTO song_entry (entry_id, year, country_code, performer, song, place_contest)
VALUES (1720, 2024, 'ch', 'Nemo', 'The Code', 1);
INSERT INTO performance (entry_id, round_id, running_order, place, points, points_tele, points_jury)
VALUES (1720, 104, 21, 1, 591, 226, 365);
COMMIT;

-- Check: the four rows are there.
SELECT song_entry.year, country.name, song_entry.performer, song_entry.song,
       performance.place, performance.points
FROM performance
JOIN song_entry ON song_entry.entry_id = performance.entry_id
JOIN country ON country.country_code = song_entry.country_code
WHERE song_entry.year = 2024;

-- Part 2. A transaction that fails halfway. The UPDATE and the first vote are valid.
-- The second vote is Switzerland giving itself 12 points, which the CHECK constraint rejects.
BEGIN;
UPDATE performance SET running_order = 22 WHERE entry_id = 1720 AND round_id = 104;
INSERT INTO vote (round_id, from_country, to_country, total_points) VALUES (104, 'se', 'ch', 12);
INSERT INTO vote (round_id, from_country, to_country, total_points) VALUES (104, 'ch', 'ch', 12);
COMMIT;

-- After the error PostgreSQL ignores every statement until the transaction ends. End it:
ROLLBACK;

-- Check: the valid changes were undone too. running_order is still 21 and there are no votes.
SELECT performance.running_order,
       (SELECT COUNT(*) FROM vote WHERE round_id = 104) AS votes_in_round_104
FROM performance
WHERE entry_id = 1720 AND round_id = 104;

-- Part 3. Remove the 2024 contest again. Children first, because of the foreign keys.
BEGIN;
DELETE FROM performance WHERE round_id = 104;
DELETE FROM song_entry WHERE entry_id = 1720;
DELETE FROM round WHERE round_id = 104;
DELETE FROM contest WHERE year = 2024;
COMMIT;

-- Check: no rows are left for 2024.
SELECT COUNT(*) AS contests_2024 FROM contest WHERE year = 2024;
```

Result: run by hand in pgAdmin, one part at a time. Part 1 inserts 4 rows. Part 2 stops with a CHECK violation on `vote` and, after ROLLBACK, the check shows running_order 21 and 0 votes. Part 3 deletes the 4 rows.

Why it is meaningful: A contest is only usable when its year, round, entry and result exist together; the transaction guarantees that a failure halfway never leaves a contest without its rows.
